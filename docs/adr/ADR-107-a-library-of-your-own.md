# ADR-107 — An installation may read a library of its own

Status: Implemented on 2026-10-18. It changes one rule of [ADR-090](ADR-090-media-library-on-the-web.md): a release build read only the published library.

## Request

"אני רוצה לאפשר למשתמש להפחית התקנה שמפנה את הספריה לכתובת שלו ולא לpages. איך הוא יכול לעשות זאת בלי לבנות הכל מחדש", then, of an address the app cannot use: "אני לא רוצה לאפשר זאת (בעיקר בסביבות סגורות, זה עלול להתפרש כניסיון לפרוץ החוצה). אם אי ספריה, להתנהל כאילו אין ספריה.", then, of distribution in an organization: "המשתמש שמתקין בפועל צריך להיות מודע למיקום הספריה… מי שמפיץ בארגון (לא בהתקנה שקטה) יוכל לעשות זאת בלי לבנות התקנה בעצמו", and, of signing: "למה לא לחתום ב-rest ע"י Slidr?"

## Context

- The pages never name the library. They read it through the core's `media` protocol, and only `media_library.rs` knows the address. So the frontend needs no change, and the address can be chosen when the app runs.
- `SLIDR_MEDIA_URL` names another copy, but only in a development build. Before this change, pointing a release build elsewhere meant building the app again, and that build was neither signed nor updated by the released installers.
- The installer is NSIS. It is signed after it is built, so it cannot be changed per user. Tauri's updater runs a newer installer with `/UPDATE` and nothing else.
- Whoever rolls the app out to an organization wants one thing to hand people, not a build of their own, and the person who installs should not have to know where the library is. An installer that carries the address is one thing to hand out, but the address is then fixed into each copy. A machine already managed by the organization can be told once, centrally, instead.

## Decision

- **A policy sets the copy for the machine**, above the file below: `HKLM\SOFTWARE\Policies\Slidr`, the string `MediaLibraryUrl` (`HKCU` for one user). Set once for the domain with Group Policy or Intune, every machine's app reads it and runs the released installer unchanged; the person who installs sets nothing. `base_url()` reads `HKLM` then `HKCU` (`policy_url`, Windows only), each start. This is how a managed app is usually pointed at an internal service, and it keeps the released installer's own signature.
- **A file beside the executable names the copy**, for a single installer that is not rolled out through a policy: `media-library.json`, `{ "url": "https://…" }`. `base_url()` reads it when the app starts. The development variable comes first, then the policy, then the file, then the published site. The rule of the variable holds here too: HTTPS, or plain HTTP only on this machine. The byte-order mark Notepad may write is skipped. A policy or file that names no address the app may read leaves the app with **no library at all**, as when the library was never published, and never with the published one: the administrator chose a copy, and on a closed network a call to Pages would look like an attempt to get out. That covers a value that cannot be read, is not JSON (the file), has no `url`, or is not HTTPS. `base_url()` answers `None`, so no library is set up, nothing is fetched, and the protocol answers every request as unavailable. Only an installation with neither a policy nor a file reads the published library.
- **The installer writes it** (`src-tauri/windows/hooks.nsh`, `bundle.windows.nsis.installerHooks`). It takes the address from `/MEDIA=<url>` on its command line, or else copies a `media-library.json` that lies beside it. `/MEDIA=` with no address removes the file. An install with neither leaves the file alone, so an update keeps the address. An uninstall removes the file, but not the uninstall an update runs.
- **The address is parsed by hand, not with `GetOptions`.** `GetOptions` ends a value at the next `/`, so an address would come out as `https:`. The hook takes everything up to the next space, or between quotes.
- **It is not a setting of the app.** Whoever can write beside the executable, or the machine's policy key, can replace the executable too, so neither grants anything new. The Settings dialog does not offer it.
- **Slidr does not sign a per-organization installer.** A tempting shape is a service that takes the address and hands back a single installer signed by Slidr. It is refused. A signature says that the one named produced and vouches for these exact bytes; Slidr cannot vouch for bytes whose whole purpose is to point the app at a server it does not control and whose content it never sees. A service that emits Slidr-signed executables on demand is a signing-key oracle, the first thing an attacker would want, and the free SignPath Foundation certificate is for the project's own released builds. So the one who customizes the installer is the one who signs it: the organization, with its own certificate (its machines already trust it), or the released installer is used unchanged under a policy. Keeping someone else's signature over changed bytes — appending to the PKCS#7 certificate set so the Authenticode hash still matches — is the technique `EnableCertPaddingCheck` exists to stop, and is not built here.

## Consequences

- The released, signed installer serves any copy, through a policy unchanged or with an address written beside it, and so do its updates. A copy is any static site laid out like the published one (docs/media-library.md, "A library of your own"). `pnpm media:publish --dry-run --out <dir>` stages it from an author's copy.
- A library reading the `windows` crate's registry calls adds `Win32_System_Registry` to its features; on other platforms `policy_url` is a stub that reads nothing.
- An unquoted address whose path has a part beginning like one of Tauri's options (`/P`, `/R`, `/NS`, `/UPDATE`, `/ARGS`) turns that option on too. Tauri reads those with `GetOptions`, which skips quoted text, so the documentation tells users to quote the address.
- The cache is not split by address. After the address changes, the manifest of the old one stands until the new one is read: at once when the app starts online.

## Checks

- Rust: `an_installation_may_name_a_copy_of_its_own`: an address with and without its final slash, with a byte-order mark, on the loopback; plain HTTP on the network, `file:`, an empty address, plain text, `{}`, an empty file and a file that cannot be read give no library; no file gives the published one. `a_policy_is_read_above_the_installation_file`: a policy overrides the file, a policy that is no usable address gives no library, and with neither the published site. All 15 tests of `media_library.rs` pass. `policy_url`/`read_policy_value` are Windows-only, so the same `windows`-crate calls (`RegGetValueW`, `RRF_RT_REG_SZ`, `w!`) were typechecked apart against the `windows` 0.62 crate for `x86_64-pc-windows-gnu`.
- The hook was compiled with makensis 3.09 (amd64-unicode) into a stand-in of Tauri's script: its `Install` and `Uninstall` sections and `un.onInit`'s `/UPDATE`, with Tauri's `/P` check. It was run under wine 9: unquoted; quoted from cmd.exe, also with `/public/` in the path (passive stays off); the whole option quoted; lower case; followed by another option; no option and `/UPDATE` (kept); `/MEDIA=` (removed); the file beside the installer; both (`/MEDIA=` wins); the uninstall of an update (kept) and a plain uninstall (removed, folder gone).
- Tauri's own installer: `tauri bundle --bundles nsis` (CLI 2.12, the hook included from `tauri.conf.json`) around a stand-in `slidr.exe`, run under 32-bit wine. Quoted with `/public/`, then `/S /UPDATE` and `/S` (kept), `/MEDIA=` (removed), the file beside the installer, unquoted, and the uninstaller (removed).
- Not run: the app reading a policy or a copy, and the installer, on Windows.
